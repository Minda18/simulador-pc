  DETALLE DE CADA ETAPA
════════════════════════════════════════════════════════════════════════

  1. ANÁLISIS DE REQUISITOS
  ─────────────────────────────────────────────────────────────────────
  • Actores: Visitante, Usuario registrado y Administrador.
  • Requisitos funcionales:
    catálogo, build temporal, validaciones, alertas por color, costo total,
    consumo energético, builds guardadas, exportación, administración y
    autenticación con vistas por rol.
  • Requisitos no funcionales:
    interfaz en español, responsive, accesible y con tema claro/oscuro;
    seguridad, portabilidad con Docker, mantenibilidad y PostgreSQL 16.

  2. ANÁLISIS DEL SISTEMA
  ─────────────────────────────────────────────────────────────────────
  • Flujo principal:
    elegir piezas → armar build → validar → calcular costo y consumo →
    guardar o exportar.
  • Reglas previstas:
    socket CPU/placa, tipo de RAM, potencia de la fuente, formato de
    placa/gabinete, longitud de la GPU, chipset y cuello de botella.
  • Estados de validación:
    compatible (verde), advertencia (amarillo) e incompatible (rojo).

  3. DISEÑO DE SOFTWARE Y ARQUITECTURA
  ─────────────────────────────────────────────────────────────────────
  • Stack: Python 3.12 + Django 5.2, PostgreSQL 16, Vite + JavaScript,
    Docker Compose y Django Admin.
  • Arquitectura:
    navegador → Django → plantillas, admin y base de datos.
    Vite queda como frontend separado para una integración futura.
  • Decisiones clave:
    usuario personalizado, login por email, apps por dominio y reglas de
    compatibilidad modeladas como datos administrables.

  4. DISEÑO DE MÓDULOS
  ─────────────────────────────────────────────────────────────────────
  • accounts: usuario, roles, registro, login y logout.
  • catalog: marcas, tipos, componentes y reglas.
  • builds: builds guardadas y sus ítems.
  • core: inicio, catálogo público, paneles por rol y permisos.
  • Modelo de datos:
    USER → BUILD → BUILD_ITEM ← COMPONENT
    BRAND → COMPONENT ← COMPONENT_TYPE
    COMPONENT_TYPE → COMPATIBILITY_RULE

  5. CODIFICACIÓN · PUNTO DE INFLEXIÓN
  ─────────────────────────────────────────────────────────────────────
  • Entorno reproducible con Docker Compose y PostgreSQL.
  • Proyecto Django con apps separadas por dominio.
  • Modelo de usuario con roles y autenticación por email.
  • Modelos base de catálogo, reglas y builds.
  • Django Admin configurado.
  • Vistas y plantillas diferenciadas por rol.
  • El motor de reglas, las validaciones en vivo y la exportación quedan
    para la siguiente iteración.
